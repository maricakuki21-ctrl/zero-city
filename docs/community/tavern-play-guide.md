## 免费单人：两段初始故事

入口：零号城 → 酒馆 → 剧本与游戏 → 本地初始体验。

1. 选择《最后一封来信》或《雾线末班车》，填写房间名、选择代入角色。
2. 阅读当前幕剧情，按需展开线索，再选择行动；一次行动推进一幕，共三幕。
3. 每次行动都有不同回应，结局取决于最后判断或前面的准备。角色是叙事身份，不提供未说明的属性加成。
4. 《最后一封来信》需要分清邮戳、时间差和档案柜证据；《雾线末班车》需要权衡路线、设备准备、返程与救援。
5. 完成后查看结局和选择记录，可导出 JSON 复盘、重新开始另一条路线。

这是固定规则的本地剧情体验，约 5–10 分钟，不是完整规则书式跑团，也不是多人推理房。无 AI 调用，不需要 Key，不扣积分或余额。进度按当前账号保存在浏览器；刷新可继续，跨设备不自动同步，开始新局会替换本机旧局。公共账号在同一台电脑上共享本地进度，请先导出需要保留的记录。

## 多人房间：公开剧本与行动记录

公开剧本需要有已发布的有效游戏包。房主创建房间后开放房间，成员加入，房主开始游戏；玩家进入舞台记录行动，房主结束本局。

- 新房间绑定当时的游戏包版本；作者后续发布新版不偷偷改变已有房间。
- 舞台是可刷新读取的回合记录，不宣称实时语音或自动主持完整规则。
- 房间入场费以创建、加入页面和确认步骤为准。本地初始故事不收取这些费用。
- AI 主持仅在房间运行后供房主操作，需选择实际可用的资源和模型；费用与结果按真实调用处理。没有可用供应商的公共测试站不保证 AI 调用成功。
- 不会因为选择了“游戏”就执行任意上传代码；声明式包不等于任意插件沙箱。

## 自己创作

「投稿与我的剧本」填写标题、简介、正文、开场和角色信息；按当前上架流程公开剧本，并上传符合 `tavern.package.v1` 的声明式包、发布版本，然后测试开房。

缺陷反馈请附页面、操作步骤、实际/期望结果及版本号。提交 PR 后由仓库检查和维护者验证进入测试站；正式服不因任意 PR 自动更新。不要在 Issue、剧本或游戏包里填写真实密钥、密码和私人聊天记录。
